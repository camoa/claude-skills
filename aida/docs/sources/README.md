# Sources: guides, recipes, playbooks, tools and surfaces

AIDA holds the process. What it knows about your stack lives outside it, in documents it reads and
tools it runs. These pages say where that content comes from and how you add your own.

Read them in this order:

1. [Where content comes from](where-content-comes-from.md): guides, recipes and playbooks, the
   catalog, and which stage reads what.
2. [Use your own folders before the catalog](your-own-sources.md): `/aida:project add-source`,
   the folder layouts, and how a stage ranks them.
3. [Guides](guides.md): how research names them, design reads them, and review checks them.
4. [Process recipes](recipes.md): the point each recipe answers, and how a stage judges its fit.
5. [When a framework has no recipe](missing-recipe.md): what each stage does, and how to stop the
   ask to write one.
6. [Playbooks](playbooks.md): the four sources of plays, the file format, and how roles follow
   them.
7. [Add plays](add-plays.md): subscribe to a catalog set, capture a play, and list the plays.
8. [Install and run a tool](tools.md): `/aida:tool run`, `install` and `show`.
9. [The tools a recipe needs](tool-requirements.md): `/aida:tool require`, and when a stage runs
   it for you.
10. [Visual and end to end tests](surfaces.md): what a surface is, when AIDA offers the setup,
    and how to decline.
11. [Set up the surfaces](surfaces-setup.md): `/aida:surfaces` install, register and the first
    baselines.
12. [A command as the end to end surface](command-surface.md): for a project with no page to
    drive.
13. [Surfaces at review](surfaces-at-review.md): what review runs, what it does to the verdict,
    and the verifier's look at each surface.
