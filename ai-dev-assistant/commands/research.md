# Research

Phase 1 of a task. Behavior current as of v4.0.2; full prose / examples / version history in `references/research-walkthrough.md`.

> **Reading strategy:** Phase 1 is **Type B** work (audit / review / architecture analysis) — read full source and config files; do NOT grep-first. Inherited methods, annotations, and config-wired classes are invisible to grep. See `https://camoa.github.io/dev-guides/development/reading-strategy/` via `dev-guides-navigator`.

## Usage

```
/ai-dev-assistant:research <task-name>
```

## Runtime Steps

Run in order. Each "gate" step writes an audit JSON; non-bypassable unless an explicit `--skip-*` flag is supplied (records `bypass_reason`).

0. **Declare the active phase (v5.29.0+).** Run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/phase-active-write.sh" research "<task_folder>"` (Bash) **before writing anything**. The phase-command-bypass guardrail compares the artifact being written against the phase that declared itself; with nothing declared it can only report `undetermined`, which is what it did on every task until this call existed. Run it at entry, not at the end — an artifact written before the declaration is indistinguishable from one written outside the phase command. **Pass the task folder.** The session file the declaration also lands in is deleted by the SessionStart hook, so a resume or a compact mid-phase wipes it; the task-folder copy is what survives.

1. **Pre-analysis gate (v4.0.0+, always-on, non-bypassable).** Compute strong signals from task name + description (length > 500, ≥3 bullets, conjunctive phrasing — informational only). Invoke `ai-dev-assistant:analysis-agent` in description mode (`task_description_text`, codePath from `${CLAUDE_PLUGIN_ROOT}/scripts/project-state-read.sh "<project_folder>"` (Bash, parse `.codePath`), `schema_version: "1.0"`). **Normalize the agent's JSON** through `printf '%s' "<the agent's JSON>" | ${CLAUDE_PLUGIN_ROOT}/scripts/analysis-agent-normalize.sh -` (a file path works in place of `-`; the argument is **required** — called bare it prints its usage and normalizes nothing) immediately on return — it deterministically clamps `confidence` to `low` when `code_read:false` (schema invariant 2). Use the normalized JSON for everything below. **Render the verdict prompt, do not compose it:** run `${CLAUDE_PLUGIN_ROOT}/scripts/prompt-render.sh <id> signals_used="<fired signals, or (none fired)>" reasoning="<the agent's reasoning verbatim>"` (Bash), where `<id>` is `pre-analysis-decision-keep-flat`, `pre-analysis-decision-insufficient-info`, or `pre-analysis-decision-epic-candidate` — the last also takes `children_list="<one child per line>"`. **The template ID comes from `decision`** — one verdict, one template, each rendering whole; there is no conditional evaluation in the renderer and a template carrying `{{#if}}` would print its markers to the person. **Show exactly what the script printed and nothing else** — do not retype it, do not explain which branch applies, and do not add a heading above it. Block on choice. **Then** write `<task>/_pre-analysis.json` via `${CLAUDE_PLUGIN_ROOT}/scripts/gate-audit-write.sh "<task_folder>" pre-analysis "<payload>"` — **pass the `gate_specific` object on its own with `user_choice` included in it** (`references/gate-audit-schema.md` §4a); the writer builds the envelope, hoists `user_choice` to envelope level where §4 puts it, and stamps `fired_at` from its own clock. `user_choice` is one of `y` / `n` / `s` / `bypassed` — the literal key the user pressed, not a paraphrase of what it meant. Do not hand-author the envelope, never hand-author a timestamp, and **never patch the audit file after the writer has run**: write it once, after the answer is in hand. Writing before the block leaves a record that cannot hold the choice, which is what produced hand-edited audits carrying `user_choice` buried in `gate_specific` under values outside the enum. Branch: `epic_candidate + y` → `/migrate-to-epic <task> --children "<list>"`; else flat-task flow.
   - **Idempotent.** If `_pre-analysis.json` already exists, skip (re-fire requires `--re-run-pre-analysis`).
   - **Grandfathering.** If `research.md` exists AND `_pre-analysis.json` absent → soft-nudge "pre-dates v4.0.0," do not block.
   - **Skip flag.** `--skip-pre-analysis <reason>` writes audit with `bypass_reason`.

2. **Create task scaffolding.** Make `implementation_process/in_progress/<task_name>/`. Write `task.md` with frontmatter, Goal, Phase Status, Acceptance Criteria, Research Questions sections (template in walkthrough the "Output" section). Author the `## Research Questions` section as a **numbered list** — one question per `N.` item (`1.`, `2.`, …); do not use bullets and do not mix styles. Numbered is the canonical style (coherent with the `Q1`/`Q2` references and `### Q1 —` headings used throughout research.md) and is what the coverage-mapping gate counts.
   - **Stub from a framework command (v4.3.1+; generalized v4.10.0):** if the folder already exists and `task.md` carries either the literal line `**Current Phase:** Phase 0 — Scope` OR a Notes-section line starting with `Stub scaffolded by ` (emitted by `/scope` AND by `/migrate-to-epic`), treat it as a framework-scaffolded stub and overwrite `task.md` with the full Phase 1 template (preserving `alignment.md` and any other sibling files). Do not abort on the pre-existing folder in this case. Any other pre-existing `task.md` aborts as before.

2a. **New-task scope-contract requirement (v5.21.0+).** A brand-new task requires its scope contract before research is authored. Run `${CLAUDE_PLUGIN_ROOT}/scripts/alignment-read.sh "<task_folder>"` (Bash) and parse `.sections.task_level.present`. **If `false` AND this is a NEW task** (the folder was created in this run, OR `task.md` is a framework-scaffolded stub per step 2's stub detection), author the contract inline via `commands/scope.md`'s Task-Level flow **before** continuing: prefer **draft-and-confirm** (scope.md Step 2) — draft the 4 fields from the task name, description, and anything the user stated this session, show them, and take the single `[y]es / [e]dit / [c]ancel` confirm; fall to the interview (or `--grill`) only when the goal is unclear. The **artifact is required** — do not proceed to author `research.md` for a new task with no Task-Level `alignment.md`; the **elicitation is soft** — never a forced heavy interview, and depth is the user's choice. An explicit `[c]ancel` is the user's override (recorded), not a silent skip. **Legacy exception:** a pre-existing, non-stub `task.md` predates this requirement and is NOT gated here — it keeps the soft retrofit offer at step 5, unchanged. **Under `--headless`/unattended:** draft the contract from available context and record it (no interactive confirm is available), then proceed. This is the only new-task gate; `/scope` itself never blocks.

2c. **Agentic-recipe discovery + gate (capability-class, v5.12.0+; multi-recipe v5.13.0+).** Follow the full protocol in `references/agentic-recipe-resolution.md` — do not re-describe its branches here. A task may match **multiple** recipes (one per capability aspect); the gate **iterates every `kind:recipe` entry** in `coverage-map.json` and records a `recipes[]` list of per-recipe decisions, **not** a single decision. **Idempotent (but a `deferred` match must re-surface):** short-circuit this step only when **every** matched recipe has a terminal decision — `project_state.md`'s `**Agentic Recipes:**` block (equivalently `_agentic-recipe.json`'s `recipes[]`) records `decision` ∈ {`adopted`, `used_own`} for all of them, or the task matched none **with a conclusive lookup** (`recipes: []` AND `coverage-map.json`'s `recipe_lookup_status == "ok"`, the genuine `no_match` case). **An inconclusive lookup is NOT terminal:** when `recipe_lookup_status` is `index_unavailable` or `navigator_unavailable` (the shared-store index or the navigator wasn't available, so the recipe layer never actually checked — GAP-B honesty), record the status but DO NOT short-circuit; re-enter on the next attended run, same posture as a `deferred` match. If **any** matched recipe is `deferred` (recorded when an unattended run hit a match it couldn't prompt on), or there is no record at all → **re-enter the gate** so the deferred match is surfaced on this next attended run (contract step 3, the unattended branch). Do NOT short-circuit on mere `_agentic-recipe.json` existence — `deferred`/`no_match` also write it. **Re-entry is per-entry, not whole-protocol:** for each matched recipe whose `recipe_name` already holds a terminal decision (`adopted`/`used_own`) in the existing `recipes[]`, SKIP its gate prompt and carry that element forward UNCHANGED (read-merge-write — preserve its decision half AND any already-run `verifier`; a `/review` may have run before this re-entry, so never reset its `verifier` to `null`); prompt ONLY the `deferred` (or newly-appeared) entries. Otherwise: invoke the `recipe-loader` skill (Skill tool) to decompose the task **Goal** into capability aspects and write `<task_folder>/coverage-map.json` (surface its `warnings[]`); then apply `references/agentic-recipe-resolution.md` steps 3–4 **per `kind:recipe` entry** — the **hard gate with explicit escape**: no `kind:recipe` entry at all **with `recipe_lookup_status == "ok"`** → proceed generically (`recipes: []`, genuine `no_match`); no `kind:recipe` entry but `recipe_lookup_status` non-`ok` → the lookup was inconclusive, record `recipes: []` with that status and re-check next attended run (do NOT terminalize as `no_match`); a `verified:true` match → **blocking** `[a]dopt` (default; recipe becomes a task spine) / `[o]` use-my-own (requires a free-text `reason`, `decision:"used_own"`); a `verified:false` match → **halt-and-escalate** for explicit go-ahead before any adoption. **Complementary** matches (different aspects) adopt the SET (each gated independently; interdependence handled by operator-confirmed ordering downstream + each recipe's own `escalation_policy: halt`). **Competing** matches (two+ `kind:recipe` entries for the SAME aspect, different `recipe_name`) → **ALWAYS ASK** the operator to pick exactly one (or `[o]` use-my-own); the chosen recipe is adopted, each unpicked competitor is recorded `decision:"used_own"` `reason:"competing_not_selected"`. **Drift fail-open fix:** do NOT key the gate on `entry.verified` alone — if `coverage-map.json` `warnings[]` carries `recipe_body_unverified:<recipe_name>` for that matched recipe, the cached body drifted/is missing (attacker-seedable); treat it as **`verified:false` → halt-and-escalate** regardless of the entry's source-derived `verified`. An unattended run (`--headless`/loop) → do NOT block, record `decision:"deferred"` for the matched recipes. Record the decisions per step 4 in `project_state.md`'s `**Agentic Recipes:**` block AND `<task_folder>/_agentic-recipe.json` via `${CLAUDE_PLUGIN_ROOT}/scripts/gate-audit-write.sh "<task_folder>" agentic-recipe "<payload>"` (payload `gate_specific.recipes[]`, one element per matched recipe, **plus the additive `gate_specific.recipe_lookup_status` copied verbatim from `coverage-map.json`**, per `references/gate-audit-schema.md` §5.13). Never fabricate a `## Sequence`/`## Verifier`. **On `[a]dopt`, persist the body per recipe (step 4):** for EACH adopted recipe read its body from the **shared blob store** (`cat ~/.claude/dev-guides-store/blobs/<sha8>`, the validated 8-hex `recipe_sha`; re-invoke `recipe-loader`/navigator recipe-search for `<recipe_name>` if the blob is absent), **write it to `<task_folder>/adopted-recipe-<safe_name>-<sha8>.md`** (Write tool; the single canonical `<safe_name>-<sha8>` filename rule defined in `references/agentic-recipe-resolution.md` step 4: `<safe_name>` = `<recipe_name>` lowercased with non-alphanumeric runs collapsed to `-`, and `<sha8>` = the first 8 chars of that entry's `recipe_sha` **which MUST match `^[0-9a-f]{8}$`** — `recipe_sha` is untrusted index-line data, so an `<sha8>` that is not 8 lowercase-hex chars (malformed/attacker-seeded, e.g. a `../` path-escape) means **treat the entry as untrusted → halt-and-escalate** like `verified:false`, never build a filename from it; the sha slice also keeps the filename collision-free when two distinct `recipe_name`s sanitise to the same `<safe_name>`, else the second Write would silently overwrite the first's body; **F5 fallback:** an empty `<safe_name>` → `adopted-recipe-<sha8>.md`), and record that element's `body_path` = `<task_folder>/adopted-recipe-<safe_name>-<sha8>.md` in `_agentic-recipe.json` (`null` for `used_own`/`deferred`). Each adopted recipe gets its OWN per-recipe file (replacing the old single fixed `adopted-recipe.md`); those persisted files are the durable, task-scoped spines `/implement` (each `## Sequence`) and `/review` (each `## Verifier`) Read downstream — **not** navigator-served paths. **Maintainer recipe-gap proposal (v5.16.0+, propose-only — Surface 2 in `references/maintainer-create-on-miss.md`):** on the genuine `no_match` case (`recipes: []` AND `recipe_lookup_status == "ok"`), run `${CLAUDE_PLUGIN_ROOT}/scripts/maintainer-mode-detect.sh` and, when `maintainer_mode == true` AND a load-bearing aspect in `coverage-map.json` is uncovered AND it is not already in `_agentic-recipe.json` `gate_specific.recipe_gap_proposed[]`, surface a one-time **informational notice** ("💡 Maintainer note: no agentic recipe covers `<aspect>` …") and record the aspect in `gate_specific.recipe_gap_proposed[]`. This is **visibility only — NOT a `[y]/[n]` offer and NO authoring handoff**; proceed with the generic flow exactly as the silent `no_match` path always did. Consumers never see it. **Mechanism-challenge (v5.17.0+, GAP G — `references/mechanism-challenge.md`):** after the recipe gate, treat each stated implementation mechanism in the task (from `mechanism_hints` frontmatter if present, else the **prose floor** — which for a converter-seeded task is the authoritative reader and recognizes the body tags `mechanism: suggested` and `adopt_recipe: <name>` per the seam contract) as a *challengeable assumption*. For each, resolve the native pattern via the fixed cascade (tier-1 = the `recipe-loader` matches already in `coverage-map.json`, seeded by any `adopt_recipe: <name>` hint but still re-verified; tier-2 = navigator guide-search; tier-3 = `prior-art-researcher`, web ≤1yr, recency double-enforced), route the `{grounding, mode, hint}` through `${CLAUDE_PLUGIN_ROOT}/scripts/mechanism-disposition.sh`, and write `_mechanism-challenge.json` (via `gate-audit-write.sh` `mechanism-challenge`) with `challenge_ran`, `mode`, `mechanisms_hash` (computed by `${CLAUDE_PLUGIN_ROOT}/scripts/mechanisms-hash.sh` over the extracted mechanism set — never by hand), and the per-mechanism disposition. A `surface` action blocks for `[a]dopt/[k]eep` when attended; `auto_adopt` applies the native pattern unattended (verified only); `defer` records without swapping. This RUNS the challenge; `/review` later asserts it ran. Does not block the recipe `no_match` path.

3. **Dev-guides preflight (two-stage, v4.10.0+).** Hybrid detection — a deterministic Stage 1 (methodology floor + lexical catalog candidates) and an agent Stage 2 (semantic prose matching).
   - **Stage 1 (deterministic).** Run `${CLAUDE_PLUGIN_ROOT}/scripts/dev-guides-detect.sh <task_folder> --phase research` → `{ methodology_floor[], catalog_candidates[], scanned_files[], warnings[] }`. The phase-aware methodology floor (research → `plugin:tdd-workflow`, `plugin:solid`, `plugin:dry-patterns`) is ALWAYS emitted — no keyword gating. `catalog_candidates[]` is empty with `warnings:["catalog_cache_missing"]` when the catalog cache is absent; in that case the preflight also suggests running `/dev-guides-navigator` to populate it.
   - **Stage 2 (agent, prose mode).** Invoke `ai-dev-assistant:guides-matcher` in `mode: "prose"` per `references/guides-matcher-schema.md` v1.1 — `catalog_path` (shared store first, honouring `DEV_GUIDES_STORE_DIR`, with the per-project compat shim + glob as transitional fallback; snippet in `commands/validate-guides.md` Step 5b), `artifact_excerpts[]` from `task.md` + `alignment.md`, `candidate_slugs[]` = Stage 1's `catalog_candidates[].slug`. The agent keeps the seed as a floor and adds semantic/synonym matches. Skip Stage 2 silently when the catalog cache is missing (record `prose_match: { skipped: true, reason: "catalog_cache_missing" }` in the audit).
   - **Two-group preflight prompt.** Render it: `${CLAUDE_PLUGIN_ROOT}/scripts/prompt-render.sh dev-guides-preflight task_name="<task_name>" methodology_floor="<floor, one per line>" matched_domain_guides="<union of catalog_candidates + agent matched_guides, one per line, OR — none auto-matched —>"` (Bash). **Show the user exactly what the script printed and nothing else.** Do not retype it, relabel the groups, or add a heading above it. Block on `[c]/[a]/[n]` (default `[c]`): continue / scan-for-more / skip.
   - Write `_dev-guides-load.json` audit (per `references/gate-audit-schema.md`) including `phase: "research"`, `methodology_floor[]`, `catalog_candidates[]`, `matched_domain_guides[]` (the agent's semantic adds), and `guides_actually_loaded[]`. **`phase` is a required key of this payload** — `_dev-guides-load.json` is attributed to the phase that wrote it, and a payload without it both warns at the write and reads as unattributed at the end-of-phase records check. Stage 1 always runs and records the floor deterministically — the agent can add and rank but never zero it out (preserves the v4.0.0 no-bypass-by-declaration guarantee).
   - **Maintainer create-on-miss offer (v5.16.0+, Surface 1 in `references/maintainer-create-on-miss.md`).** After the audit write, run `${CLAUDE_PLUGIN_ROOT}/scripts/maintainer-mode-detect.sh` (Bash; parse `.maintainer_mode`/`.dg_src`). When `maintainer_mode == true` AND this was a **genuine domain miss** — **the Surface 1 trigger in `references/maintainer-create-on-miss.md` holds** — a load-bearing aspect in `coverage-map.json` `uncovered_aspects[]` that no guide covers, falling back to the whole-task union test only when no coverage map is readable AND the **durable** sidecar `<task>/_create-on-miss.json` does not already record a `decision` for the same `<topic>`, surface the **assertive one-time** offer in that reference (name the uncovered `<topic>`; `[y]` author via `/create-guide <topic>` in `dg_src` per the handoff rule / `[n]` skip, default / `[d]` don't ask again). Non-blocking; consumers (`maintainer_mode == false`) never see it. **Record the decision durably** (read-merge-write `<task>/_create-on-miss.json`, keyed by `topic`) — NOT in the overwrite-on-fire `_dev-guides-load.json` (mirror there for observability only) — so the `/design` Step 2 re-offer and any re-run are suppressed. **Never author here — detect, offer, hand off to `/create-guide`, STOP.**

4. **Playbook load (deterministic, v4.0.0+).** Run `${CLAUDE_PLUGIN_ROOT}/scripts/playbook-load-deterministic.sh <project_folder>` (Bash). **The script prints the `gate_specific` object on stdout; it does not write the audit** — it is handed a project folder and has no way to know which task is active. Capture that stdout and write the record yourself: `${CLAUDE_PLUGIN_ROOT}/scripts/gate-audit-write.sh "<task_folder>" playbook-load "<the payload, with `phase: "research"` added>"`. **`phase` is not optional here** — `_playbook-load.json` is attributed to the phase that wrote it, so a payload without it reads as unattributed at the end-of-phase records check, a long way from the cause. Leaving the output on stdout leaves no record at all, and the phase fails its own records check. Loads active sets + the local user playbook. Surface conflicts once-per-session per topic via `playbook-conflicts-write.sh` (precedence local > active set > generic). If a project-level `glossary.md` exists, read it for naming consistency (soft — never blocks; absent is fine).

5. **Alignment retrofit + phase-level offer.** Run `${CLAUDE_PLUGIN_ROOT}/scripts/alignment-read.sh "<task_folder>"` (Bash) and parse its JSON. If `.sections.task_level.present == false` AND task folder pre-existed AND pre-analysis didn't fire this session: offer task-level retrofit (4 questions, default `[skip]`). Then offer phase-1 scope per the table in `references/research-walkthrough.md` the "Phase 1 alignment sub-step" section (default `[n]`). **Render either offer:** `${CLAUDE_PLUGIN_ROOT}/scripts/prompt-render.sh scope-contract-offer task_name="<task_name>" level="this task"` for the task-level offer, `level="the research phase"` for the phase-1 one. **Show exactly what the script printed.** Do not compose your own wording, do not name a file the person does not have, and never name the step number — a step number is an address inside this file, not something a person can look up. **(v5.10.2+)** that table now ends in a **floor branch**: when no task-level scope, no phase-1 scope, and no pre-analysis scope signal are present, the **task-level** scope is offered once anyway (matching `/design` and `/implement`, which offer task-level retrofit whenever `task_level.present: false`) — so a task entered directly via `/research` still gets one scope offer at this highest-leverage moment, without re-dispatching `ai-dev-assistant:analysis-agent`. The floor offers task-level (not phase-1) because phase-level scope assumes a task-level contract exists. It is mutually exclusive with the pre-analysis scope nudge; it is NOT guarded against `/next`'s offer (which persists nothing on decline), so a `/next`-declined task may see it again — an accepted soft-nudge cost. On `[y]` for either offer: execute the matching task-level / `--phase 1` flow from `commands/scope.md` inline (do NOT shell out).

5a. **Internal prior art (v5.26.0+, `references/internal-prior-art.md`).** Search the project's own code and its own record of what it already built, BEFORE the outward search at step 6. Full semantics live in that reference; do not restate them here.
   - **Read `run_mode`** — `${CLAUDE_PLUGIN_ROOT}/scripts/project-state-read.sh "<project_folder>"` → `.runMode`, with the optional task override via `${CLAUDE_PLUGIN_ROOT}/scripts/fm-read.sh "<task_folder>"` → `.run_mode`. Absent or bad → `interactive` (fail-closed; an unset mode never grants autonomy).
   - **Ask the user what prior art they know of.** Attended: render it — `${CLAUDE_PLUGIN_ROOT}/scripts/prompt-render.sh prior-art-ask project_name="<project_name>"` (Bash) — show exactly what it printed, and record the answer. Unattended: record `user_prior_art.asked: false` with an `unasked_reason`. **Silence is never recorded as "none known"** — nobody was asked.
   - **Index the ledger.** `${CLAUDE_PLUGIN_ROOT}/scripts/ledger-index.sh "<project_folder>"` (add `--with-criteria` only when a hit needs criterion-level comparison; the lean form is ~32% smaller and is the default for a reason). Zero tasks is a `skip_reason`, not a failure.
   - **Check map currency.** When `project_state.md` records a `**Code Map:**`, run `${CLAUDE_PLUGIN_ROOT}/scripts/map-currency.sh --map-path <path> --repo <codePath>`. `stale` → disclose it and search the code directly anyway. `absent` is the ordinary default, not a problem. **Never run the mapping tool** — setup is consented and manual, refresh is recommended and never performed.
   - **Search.** Invoke the `internal-prior-art-finder` skill (Skill tool) with the capability aspects from `<task_folder>/coverage-map.json` `task_aspects[]` — **copied verbatim, never re-derived** (the coverage-map contract forbids re-deriving them, and the join downstream is on the aspect string). Ledger first (capability altitude), then code (what shipped). Per source record `searched: true` or a non-null `skip_reason`. The skill returns **scalars plus a pointer** to `research/internal-prior-art.md`; its findings prose never enters this command's context.
   - **Route each hit.** Serialize the finder's `dimensions[]` objects into the kernel's flag strings — this is the caller's job and the mapping is fixed, so two runs cannot disagree: `--dimensions` is every dimension as `class:name`, comma-joined; `--measured` is only those with `kind: "measurable"` AND a non-empty `value`, as `class:name=value`, semicolon-joined; `--absorbs` is the hit's `absorbs_superseded_use_case`. **The kernel never sees `kind`** — it infers "something was measured" from `--measured` being non-empty, which is exactly why a dimension marked `measurable` with no `value` must be left out of `--measured` rather than passed with an empty one. Then run `${CLAUDE_PLUGIN_ROOT}/scripts/prior-art-disposition.sh --verdict <reuse|extend|supersede> --mode <attended|unattended> [--dimensions "class:name,..."] [--measured "class:name=value;..."] [--absorbs true|false]`. The kernel owns the matrix AND the citation floor; **never hand-write `effective_verdict`**, or the record and the enforcement drift. Attended, an admissible hit **blocks** with `[r]euse / [e]xtend / [s]upersede / [b]uild anyway (requires a reason)` — the escape is one keystroke plus a recorded reason, the same shape as the agentic-recipe gate's `[o]`. Unattended, dispatch `ai-dev-assistant:prior-art-verdict-confirmer` (Task tool) per hit and read its `_prior-art-confirm-<aspect>.json` sidecar back as scalars; an absent sidecar records `confirmation: "no_return"` and is **never** folded into agree or disagree.
   - **Compare against the cascade.** For each hit, set `cascade_comparison` against what the resolver cascade selected for that aspect: no covering recipe → `no_covering_recipe`, and add the aspect to `recipe_gap[]`; a hit that contradicts the tier-1/tier-2 pattern → `disagrees` (this is the drift that produces two solutions to one problem). Mirror `recipe_gap[]` into `_agentic-recipe.json`'s existing `gate_specific.recipe_gap_proposed[]` — do not open a second gap surface.
   - **A settled supersede owes a migration.** Either an explicit recorded decision to refactor within this task, or a follow-on ai-dev-assistant task created for the migration and cross-linked, with a `**Pending duplicate:** <task>` line in its `task.md` so `ledger-index.sh` surfaces it to the NEXT search. Never silently refactor, never silently defer.
   - **Record.** `${CLAUDE_PLUGIN_ROOT}/scripts/gate-audit-write.sh "<task_folder>" internal-prior-art "<payload>"` per `references/gate-audit-schema.md` §5.16, and write `research/internal-prior-art.md` (the subject file) with the hub's Research Index linking it. **The subject file is written even when nothing was found** — "we looked and found nothing" is the evidence a later "build custom" needs.
   - **Nothing found → continue to step 6 unchanged.** The cost of a clean run is one question and one short subject file.

6. **Author research findings.**
   - **Resolve the framework prior-art search method (recipe-resolution protocol).** Before invoking the researcher, follow the shared recipe-resolution protocol in `references/recipe-resolution.md` with `phase: research` and the active project's `<project_folder>`. That protocol invokes the `process-recipe-loader` skill, resolves each framework's research recipe (project_state-first, then source order, else `action:ask-user`), records the source in `project_state.md`, and defines how to follow each result: Read the `body_path` (never streamed), follow `verified:true` directly, surface `verified:false` for human review first, and on `action:ask-user` ask the user for a path or to research. Surface any loader `warnings[]` (for example `no_frameworks_defined`, `navigator_unavailable:<framework>`, `recipe_not_published:<framework>`) to the user. The COMMAND owns this resolution and injects the resolved recipe body into the researcher's context; the agent stays generic and needs no Skill tool.
   - **Read the body and inject it verbatim.** For each framework result with `available:true`, Read its `body_path` with the Read tool (it is never streamed), gate it by `verified` (follow `verified:true`; surface `verified:false` for human go-ahead first), then dispatch `ai-dev-assistant:prior-art-researcher` with the Task tool and include the recipe body **verbatim** in the agent's prompt, inside the delimited block from `references/recipe-resolution.md` step 4 (`=== RESOLVED RECIPE (key=…, source=…, verified=…) === <body> === END RECIPE ===`). Reading `body_path` and dispatching the agent without including the body is a bug: the agent would have no search method to follow.
   - **Record the resolution (recipe-resolution.md step 7).** After resolving, write `<task>/_recipe-load.json` via `${CLAUDE_PLUGIN_ROOT}/scripts/gate-audit-write.sh "<task_folder>" recipe-load "<payload>"` (payload per `references/gate-audit-schema.md` §5.12): every framework considered with its `source`/`verified`/`available`/`body_path`, plus a `bypass` object for any no-recipe outcome (`no_frameworks_defined` etc.). Research carries the body verbatim (not declaration-bearing), so `declarations_audit` is `null` and no lint runs. Observability only — never blocks.
   - **No body resolved → do not dispatch.** Run `prior-art-researcher` **only** when a `body_path` resolved for the framework. On `no_frameworks_defined`, follow the framework-resolution branch in `references/recipe-resolution.md` step 6, which runs the cascade in `references/framework-resolution.md` (identify the framework by reading the repository → check what the catalogs carry for it → ask the user → research → record `_framework.json` and write `**Frameworks:**` → re-resolve once → proceed; unattended: record gap + skip); on `action:ask-user` ask the user for a path or to research and proceed per the answer; on a framework that resolved nothing skip it with a clear note. Per `references/recipe-resolution.md` step 6, the generic-agent dispatch needs a `body_path` to inject.
   - **Invoke `ai-dev-assistant:prior-art-researcher` agent + `core-pattern-finder` skill.** Run the generic `prior-art-researcher` against the resolved recipe's prior-art search method (the injected body): it follows that method to find and evaluate existing solutions, then returns structured findings.
   - **Scope the outward search by aspect (v5.26.0+).** The dispatch carries `<task_folder>/coverage-map.json` `task_aspects[]` **and** the per-aspect recipe decisions from `_agentic-recipe.json`, so the search is goal-driven rather than pointed at the task as an undifferentiated blob. Before this, the aspects were derived at step 2c and the search that most needs them never saw them, so an aspect an adopted recipe already answered was researched again from scratch and an aspect flagged `uncovered` got no extra attention. Per aspect:

     | aspect state | outward search |
     |---|---|
     | answered by an **adopted** agentic recipe | **skipped**, recording the recipe name as the skip reason |
     | covered by a guide only | searched |
     | in `uncovered_aspects[]` | searched, and **prioritised** |
     | already hit by step 5a's internal search | searched only for the improve-or-replace comparison |

     **Every finding names the aspect it answers.** A finding carrying no aspect is rejected, the same shape as the disposition kernel's citation floor. A coverage map with zero aspects degrades to the whole-task behaviour and records why, rather than dispatching nothing.
   - **Carry the internal record forward.** Inject `_internal-prior-art.json`'s summary into the researcher's prompt so the outward search knows what the project already has and is looking for what fills a gap. This changes what the search is pointed at; it does not change **when** it runs, and it does not remove the requirement that a process-recipe body resolved first.
   - **Research questions about current behavior are answered by observing the system, not by reading about it (v5.30.5+).** When a question asks what the software does *today* rather than which approach to take, the answer comes from the running system, and Phase 1 owns that read. **Query it through the interface it presents — its API, its command-line tooling, its HTTP surface — never past that into its datastore.** The datastore does not apply the application's access rules, does not know derived, cached or unsaved state, and does not run the layers that decide what a user sees; a row count answers a question about rows when the question was about behavior. Where the resolved process recipe names the stack's read tooling, follow it; where none covers it, record the gap as a finding rather than reaching past the application. Every behavioral claim becomes its own `research/<subject>.md` subject with a Coverage Mapping row, stating what was run, against which environment, on what date, and which states were not reached. See `references/research-walkthrough.md` the "Observing the system under study" section.
   - **Per-subject research files (v4.10.0+).** Save each distinct subject the research investigates as **its own `research/<subject>.md` file** — one file per investigated subject (an existing third-party library, an integration approach, a framework (first-party) subsystem, a competing option), named after that subject, holding that subject's complete findings. `research.md` is the **index/hub**: Problem Statement, a Research Index table linking the subject files, Recommendation, Key Patterns to Apply, Decision Log. The hub synthesizes and links — it does NOT restate each subject's detail, so `/design` and `/implement` load only the subjects they need instead of one monolithic file. A flat single-file `research.md` is fine only when research genuinely covered a single subject.
   - Add `## Coverage Mapping` H2 mapping each Research Question (and task-level AC if present) to the research that addresses it. **`## Coverage Mapping` MUST stay in the `research.md` hub** — the coverage-mapping gate reads only `research.md`; its rows may point into `research/<subject>.md` files. See `references/research-walkthrough.md` the "Output" section.
   - **Effort-adaptive depth.** The active effort level is `${CLAUDE_EFFORT}`. Scale research depth to it: `low` → confirm the single most likely known pattern and stop; `medium`/`high` → the standard prior-art + framework-pattern pass; `xhigh`/`max` → corroborate across multiple sources, probe edge cases, enumerate alternatives in the Decision Log. Depth scales; the gates (Steps 1, 3, 4, 7) always run regardless of effort.

7. **Coverage-mapping gate (v4.0.0+, non-bypassable).** Run `${CLAUDE_PLUGIN_ROOT}/scripts/coverage-mapping-check.sh <task_folder>`. Branch on `verdict`:
   - `pass` → write `_coverage-mapping.json` with `user_choice: "phase_marked_complete"`. Continue.
   - `fail` → render it: `${CLAUDE_PLUGIN_ROOT}/scripts/prompt-render.sh coverage-mapping-fail missing_questions="<list>"` (Bash), and show exactly what it printed. Block. `[a]bort` → audit `phase_left_incomplete`, refuse to mark Phase 1 `[x]`, exit 1. `[s]kip` → prompt for free-text reason, audit `bypassed` + `bypass_reason`, allow Phase 1 `[x]`.
   - **Skip flag.** `--skip-coverage-check <reason>` writes audit `bypassed` and proceeds.

7z. **Records check — did the phase produce what it owes? (v5.28.2+)** Before marking Phase 1 done, run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/phase-records-check.sh" "<task_folder>" --phase research` and read `.verdict` and `.missing_required`.

   **On `incomplete`, do NOT mark Phase 1 `[x]`.** Print each missing required record with the `producer` and `step` the check names, then go run that component. A missing record almost always means its skill was not invoked — the phase was carried out by hand instead. That is the failure this check exists for, and it is not cosmetic: the hand-rolled version produces terminal output and no artifact, so `/review`'s fail-closed assertions have nothing to read, later phases lose the pointer, and any conversation that lives inside the skipped skill (the code-map question in `internal-prior-art-finder`, for one) never happens at all.

   **Reading the protocol is not performing it.** A session that understands step 5a well enough to run the search itself will produce a good answer and leave `_internal-prior-art.json` absent. Invoke the named skill; do not reimplement it because the task looks small or because the answer seems obvious from here.

   `unknown` (no contract encoded for the phase) is not a pass — say the check could not run. Conditional records that did not fire are not missing and never block.

8. **Mark Phase 1 `[x]`** in `task.md` (only on pass or bypass).

9. **Post-research epic check (v3.13.5+).** Re-invoke `ai-dev-assistant:analysis-agent` in folder mode with full task context. **Normalize the returned JSON** through `printf '%s' "<the agent's JSON>" | ${CLAUDE_PLUGIN_ROOT}/scripts/analysis-agent-normalize.sh -` (a file path works in place of `-`; the argument is **required** — called bare it prints its usage and normalizes nothing) before branching (deterministic `confidence` clamp, schema invariant 2). Branch on `decision`:
   - `keep_flat` / `insufficient_info` → silent, proceed.
   - `epic_candidate` → display offer with proposed children, default `[n]`. `[y]` → `/migrate-to-epic`, stop. `[d]` → show rationale + signals_used, re-ask. `[n]` → continue.

10. **Traceability walkthrough (opt-in).** One-line `[y]/[n]` prompt (default `[n]`). On `[y]`: pull questions from `task.md` Research Questions + alignment task-level AC; map each to research.md sections; mark "NOT YET ADDRESSED" honestly; print table; three-way `[c]/[r]/[d]` (default `[c]`).

11. **Update `project_state.md`** with current task.

12. **Run `${CLAUDE_PLUGIN_ROOT}/scripts/session-context-write.sh "<project_name>" "<project_folder>" "<task>" "<task_path>"`** (Bash) with resolved project + task.

13. **Distill-and-drop seam (v5.18.0+, `run_mode`-aware — advisory, never blocks).** After the durable pointer is written and Phase 1 is marked `[x]`, run the end-of-phase distill seam per `references/orchestration-context-hygiene.md` §2. It sheds this phase's context residue *before* the raw exchange is compacted; the live research orchestration has already finished above.
    - **Read `run_mode`** — `${CLAUDE_PLUGIN_ROOT}/scripts/project-state-read.sh "<project_folder>"` → `.runMode` (project dial), with an optional task override via `${CLAUDE_PLUGIN_ROOT}/scripts/fm-read.sh "<task_folder>"` → `.run_mode` (`null` = inherit). Absent/bad → `interactive` (fail-closed; an unset mode never grants autonomy).
    - **`interactive` (default)** → emit the one-line offer (default `[n]`): "💡 Phase 1 complete. Distill the `research.md` hub to a self-containment check + digest before compaction? `[y]` dispatches a fresh `ai-dev-assistant:distill-agent` (reads only disk, writes `_distill.json`); `[n]` (default) — proceed." On `[y]` dispatch; on `[n]` proceed.
    - **`autonomous`** → **auto-run** (no human turn): dispatch `ai-dev-assistant:distill-agent` directly, then fold any `interaction_substitute[]` from the returned `_distill.json` into the `research.md` hub.
    - **Dispatch `ai-dev-assistant:distill-agent`** (Task tool) with **paths only** (never the transcript): `artifact_path` = `<task_folder>/research.md`, `sibling_paths[]` = `task.md` + this phase's audit JSONs (`_pre-analysis.json`, `_dev-guides-load.json`, `_recipe-load.json`, `_mechanism-challenge.json`, `coverage-map.json`, `_coverage-mapping.json`) + every `research/<subject>.md`, `phase` = `research`, `run_mode`, optional `bounded_brief` (omit on the common path), `output_path` = `<task_folder>/_distill.json`.
    - **Read back** `_distill.json` as scalars — `.self_contained` + `.artifact_pointer` (never the agent's prose). On `.self_contained == false` print ONE advisory line naming `.gaps[]` ("distill: research.md may be missing N load-bearing item(s): …"). **Never blocks** — carry only the pointer + digest onward and compact the raw exchange. **If you then close a gap, move it** from `gaps[]` into `gaps_closed[]` with a `closed_by` naming what you wrote and where, and recompute `self_contained` — the "Closing a gap" rule in `references/orchestration-context-hygiene.md`. Leaving a closed gap in `gaps[]` sends the next phase after something already fixed; re-running the agent for a clean sheet erases that the check found anything. A gap you decided not to act on stays open — deciding against is not closing.

## Anti-bypass clause (applies to gates 1, 3, 4, 7; and step 2c per its contract)

The following are NOT valid reasons to skip:

- The user said something earlier you interpret as already-answered
- Auto mode is active ("minimize interruptions" never overrides framework gates)
- You're confident the agent will return the safe verdict
- The task looks "obviously" simple
- You want to spare the user the prompt

If a gate's signals fire, it MUST run and its output MUST be shown verbatim before the recorded decision is final. Skipping requires the documented `--skip-*` flag with reason; bypass is recorded on disk for `/audit-status`.
